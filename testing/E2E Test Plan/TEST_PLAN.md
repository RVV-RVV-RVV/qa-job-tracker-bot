## Section 5: Security, DB Integrity & API (Postman та AppSheet)

### Test Case 21: [AppSheet] Втручання через AppSheet (God Mode)
**Priority:** High
| Step | Action | Expected Result |
| :--- | :--- | :--- |
| **1** | У боті додати компанію зі статусом "нова вакансія". | Компанія з'являється у списках бота. |
| **2** | Відкрити Google Таблицю (імітація AppSheet) і вручну змінити статус на "Відмова". | Статус успішно збережено в БД. |
| **3** | У боті натиснути `Cover Letter` або `Аналіз відповіді` (для цієї компанії). | Бот коректно "не бачить" компанію в списках активних, система не "крашиться" (синхронізація відбулась). |

### Test Case 22: [Data] Перевірка безпечного авто-сортування (ArrayFormula Bypass)
**Priority:** Critical
| Step | Action | Expected Result |
| :--- | :--- | :--- |
| **1** | Додати кілька вакансій з різними статусами. У стовпцях D та F переконатися, що стоять `ARRAYFORMULA(...)`. | БД підготовлена. |
| **2** | Запустити функцію `autoSortSheet` (або зробити дію в боті, яка її тригерить). | Рядки відсортовані за пріоритетами. Формули в D та F не перетворилися на статичний текст і не видали помилку `#REF!`. |

### Test Case 23: [API] Спроба доступу з чужого Telegram ID
**Priority:** Critical
| Step | Action | Expected Result |
| :--- | :--- | :--- |
| **1** | У Postman відправити POST-запит на Webhook URL з payload, де `message.chat.id` дорівнює умовному `123456789` (не дорівнює системному `MY_TELEGRAM_ID`). | Webhook повертає "OK" (щоб уникнути спаму від Telegram), але функція блокує виконання і відправляє неавторизованому користувачу повідомлення: *"⛔️ Доступ заборонено. Цей бот є приватним інструментом..."*. |

### Test Case 24: [API] Обробка пустого запиту (Health Check)
**Priority:** Medium
| Step | Action | Expected Result |
| :--- | :--- | :--- |
| **1** | Відправити GET або пустий POST-запит на Webhook URL (без JSON payload). | Webhook коректно обробляє запит через health-check блок (`if (!e || !e.postData)`) і повертає `HtmlService.createHtmlOutput("OK")` без падіння скрипта. |
